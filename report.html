Good Health & Well-Being

🌿 UN Sustainable Development Goal 3 (SDG-3)

સંપૂર્ણ ફુલ-સ્ટેક આર્કિટેક્ચર, ડેટાબેઝ સ્કીમા, CRUD ઓપરેશન્સ અને વાઇવા ગાઇડ

આ દસ્તાવેજ પ્રોજેક્ટના દરેક ઘટક (Frontend, Backend, MySQL Database, Security, Calculators, REST APIs) ની વિગતવાર સમજૂતી આપે છે. જે સભ્યોએ કોડ જોયો પણ ન હોય તેઓ પણ બાહ્ય અને આંતરિક પરીક્ષકો (Examiner/Ma'am) ના તમામ ટેકનિકલ પ્રશ્નોના સંપૂર્ણ આત્મવિશ્વાસ સાથે જવાબ આપી શકે તે રીતે તૈયાર કરાયો છે.

પ્રોજેક્ટ પ્રકાર (Architecture) Full-Stack Web App (3-Tier MVC Architecture)
ફ્રન્ટએન્ડ (Frontend Stack) HTML5, Modern CSS3, Vanilla JS, Responsive UI
બેકએન્ડ (Backend Server) Node.js, Express.js (REST APIs, JWT, Helmet)
ડેટાબેઝ (Database Engine) MySQL (InnoDB, Foreign Keys, Pool) + In-Memory Fallback
મુખ્ય ફંક્શનલિટી (Core Focus) Complete CRUD Operations on Category Tasks & Logs
સ્થાનિક સર્વર પોર્ટ (Default Port) http://localhost:8080

૧. પ્રોજેક્ટ પરિચય, હેતુ અને વિઝન (Project Overview & POV)

૧.૧ પ્રોજેક્ટનો Point of View (POV)

આ પ્રોજેક્ટનો મુખ્ય ઉદ્દેશ્ય માત્ર એક સાદી સ્ટેટિક વેબસાઇટ બનાવવાનો નથી, પરંતુ સંપૂર્ણ વર્કિંગ ફુલ-સ્ટેક વેબ એપ્લિકેશન (Full-Stack Web Application) તૈયાર કરવાનો છે. જેમાં વપરાશકર્તા ઇન્ટરફેસ (Frontend), સર્વર લોજિક (Backend REST APIs) અને રિલેશનલ ડેટાબેઝ (MySQL) એકબીજા સાથે રીઅલ-ટાઇમમાં અરસપરસ જોડાયેલા છે અને દૈનિક સ્વાસ્થ્ય કાર્યો પર યોગ્ય CRUD (Create, Read, Update, Delete) ઓપરેશન્સ અમલમાં મૂકે છે.

૧.૨ યુનાઇટેડ નેશન્સ SDG-3 સાથે સુસંગતતા (UN SDG-3 Alignment)

આ પ્રોજેક્ટ યુનાઇટેડ નેશન્સના ૧૭ ટકાઉ વિકાસ લક્ષ્યાંકો પૈકી લક્ષ્યાંક ૩: Good Health and Well-Being પર આધારિત છે. આ પ્લેટફોર્મ સામાન્ય નાગરિકો, વિદ્યાર્થીઓ અને કામ કરતા વ્યાવસાયિકોને જીવનશૈલી સંબંધિત રોગો (જેવા કે ડાયાબિટીસ, હાઈ બ્લડ પ્રેશર, માનસિક તણાવ, અનિદ્રા) થી બચવા માટે રોજિંદી સ્વસ્થ આદતો કેળવવામાં મદદ કરે છે.

૧.૩ સુખાકારીના ૫ મુખ્ય સ્તંભો (The 5 Wellness Pillars)

સ્તંભ (Pillar) ફોકસ એરિયા (Focus Area) ઇન્ટરેક્ટિવ ટૂલ (Interactive Feature)
🥗 પૌષ્ટિક આહાર (Food) બેલેન્સ્ડ પ્લેટ મોડેલ (૫૦% શાકભાજી/ફળો, ૨૫% અનાજ, ૨૫% પ્રોટીન) Water Intake Calculator (વજન અને શ્રમ મુજબ પાણીનું પ્રમાણ)
🏃 શારીરિક કસરત (Exercise) રોજિંદા સ્ટેપ્સ, બોડીવેઇટ વર્કઆઉટ્સ અને યોગાસન 5-Minute Stretch Timer (ડેસ્ક પર બેઠા સ્ટ્રેચિંગ માટે ટાઇમર)
🧘 માનસિક શાંતિ (Mental Health) તણાવ મુક્તિ, માઇન્ડફુલનેસ અને 5-4-3-2-1 ગ્રાઉન્ડિંગ ટેકનિક 4-7-8 Breathing Circle (શ્વાસ લેવા અને છોડવા માટે લાઇવ એનિમેશન)
🌙 ગાઢ ઊંઘ (Sleep) ૭-૯ કલાકની ગુણવત્તાયુક્ત ઊંઘ અને ઇવનિંગ ડિજિટલ ડિટોક્સ 90-Min Sleep Cycle Calculator (થાક્યા વગર જાગવા માટેનો સમય)
✨ સ્વસ્થ આદતો (Habits) હેબિટ સ્ટેકિંગ ("પહેલાની આદત + નવી સ્વસ્થ આદત") Daily Habit Tracker (દૈનિક ચેકલિસ્ટ, પ્રોગ્રેસ બાર અને સ્ટ્રીક)
💡 પ્રેઝન્ટેશન કી-પોઇન્ટ (Ma'am સમક્ષ બોલવા માટે):
"મેડમ, અમારા પ્રોજેક્ટની ખાસિયત એ છે કે તે માત્ર થિયરી નથી બતાવતો, પણ યુઝરને લાઈવ કેલ્ક્યુલેટર્સ આપે છે અને યુઝરે કરેલા કાર્યોનો ડેટાબેઝમાં દૈનિક રેકોર્ડ સાચવીને તેનો ડેઇલી હેલ્થ સ્કોર અને રિકવરી પ્લાન તૈયાર કરે છે."

૨. સિસ્ટમ આર્કિટેક્ચર અને ટેકનોલોજી સ્ટેક (System Architecture)

પ્રોજેક્ટ 3-Tier MVC (Model-View-Controller) આર્કિટેક્ચર પર આધારિત છે:

સ્તર (Tier) ટેકનોલોજી (Technology) જવાબદારી (Responsibility)
૧. Presentation Tier (Frontend) HTML5, CSS3, JavaScript (ES6+), Fetch API યુઝર ઇન્ટરફેસ રેન્ડરિંગ, ફોર્મ વેલિડેશન, એનિમેશન, કેલ્ક્યુલેશન અને એસિન્ક્રોનસ API કોલ્સ.
૨. Application Tier (Backend Server) Node.js & Express.js (પોર્ટ 8080) બિઝનેસ લોજિક, RESTful API રાઉટીંગ, ઓથેન્ટિકેશન (JWT), સિક્યોરિટી મિડલવેર (Helmet, Rate Limiter).
૩. Data Tier (Database) MySQL (MySQL2 Connection Pool) ડેટાબેઝ સ્કીમા, ટેબલ રિલેશન્સ, કમ્પોઝિટ કીઝ, ઇન્ડેક્સિંગ અને ઓટોમેટિક ડેટા પર્સિસ્ટન્સ.
૪. Resilient Fallback Engine In-Memory JavaScript Store જો લોકલ મશીનમાં MySQL બંધ હોય, તો પણ સિસ્ટમ ક્રેશ થયા વગર મેમરી સ્ટોરમાં બધી API રન કરે છે.
૫. Alternate Java Server Java 11+ (HealthAppServer.java) પ્રોજેક્ટમાં જાવા આધારિત બિલ્ટ-ઇન HTTP સર્વર પણ સામેલ છે જે સ્ટેટિક ફાઇલ્સ અને સેમ્પલ API સર્વ કરે છે.

૨.૧ ટેક સ્ટેકની પસંદગીના કારણો (Why this stack?):

  • Node.js & Express: Non-blocking, event-driven આર્કિટેક્ચર હોવાથી હાઈ-સ્પીડ API રિસ્પોન્સ આપે છે અને સરળતાથી RESTful એન્ડપોઇન્ટ્સ બનાવી શકાય છે.
  • MySQL Database: સ્ટ્રક્ચર્ડ હેલ્થ ડેટા (યુઝર પ્રોફાઇલ, ટાસ્ક ડિટેલ્સ, કેલેન્ડર હિસ્ટ્રી) સાચવવા માટે રિલેશનલ ડેટાબેઝ સર્વશ્રેષ્ઠ છે જેમાં ACID પ્રોપર્ટીઝનું પાલન થાય છે.
  • Vanilla JavaScript (No Heavy Frameworks): કોઈ વધારાની ભારે લાઈબ્રેરી વિના પ્યોર જાવાસ્ક્રિપ્ટ વાપરવાથી પેજ લોડિંગ અત્યંત ઝડપી બને છે અને બ્રાઉઝરની મેમરી ઓછી વપરાય છે.

૩. ડેટાબેઝ સ્કીમા અને ટેબલ્સનું વિશ્લેષણ (Database Schema & Tables)

ડેટાબેઝનું નામ good_health_db છે. ડેટાબેઝમાં કુલ ૮ મુખ્ય ટેબલ્સ તૈયાર કરવામાં આવ્યા છે:

૧. users ટેબલ (વપરાશકર્તા એકાઉન્ટ માહિતી)

યુઝરની ઓળખ અને સિક્યોર લોગિન માહિતી સાચવે છે.

ફીલ્ડ (Column)ડેટા ટાઇપવિગત અને ઉપયોગ
idINT AUTO_INCREMENT PRIMARY KEYદરેક યુઝરનો યુનિક ક્રમાંક.
nameVARCHAR(100) NOT NULLયુઝરનું પૂરું નામ.
emailVARCHAR(150) NOT NULL UNIQUEયુનિક ઇમેઇલ (ડુપ્લિકેટ રજીસ્ટ્રેશન અટકાવે છે).
password_hashVARCHAR(255) NOT NULLbcryptjs વડે સુરક્ષિત રીતે હેશ કરેલો પાસવર્ડ.
last_login_atTIMESTAMP NULLછેલ્લા લોગિનનો સમય.
created_atTIMESTAMP DEFAULT CURRENT_TIMESTAMPએકાઉન્ટ બન્યાની તારીખ.

૨. કેટેગરી-વાઇઝ ટાસ્ક ટેબલ્સ (tasks_food, tasks_exercise, tasks_mental, tasks_sleep, tasks_habits)

દરેક હેલ્થ પિલર માટે અલગ ટેબલ છે જેથી ડેટા વ્યવસ્થિત અને ઝડપી ક્વેરી થઈ શકે.

ફીલ્ડ (Column)ડેટા ટાઇપવિગત અને ઉપયોગ
idVARCHAR(64) PRIMARY KEYટાસ્ક આઈડી (દા.ત. 'task_a9f1b2').
user_idINT NULL, FOREIGN KEY (users.id)જો NULL હોય તો વૈશ્વિક/જનરલ ટાસ્ક, જો ID હોય તો યુઝરનો કસ્ટમ ટાસ્ક.
condition_keyVARCHAR(50) DEFAULT 'general'મેડિકલ સ્થિતિ (general, diabetes, hypertension, stress, heart).
nameVARCHAR(255) NOT NULLટાસ્કનું શીર્ષક (જેમ કે "સવારે ૨૦ મિનિટ યોગ").
tipTEXT NULLટાસ્ક કરવાનો સ્વાસ્થ્ય લાભ કે ટિપ.
iconVARCHAR(16) DEFAULT '📝'ટાસ્ક આગળ દેખાતો ઇમોજી આઈકોન.
is_activeTINYINT(1) DEFAULT 1સોફ્ટ ડિલીટ ફ્લેગ (1 = સક્રિય, 0 = ડિલીટ થયેલ).

૩. task_completions ટેબલ (રોજિંદા ટાસ્કનું સ્ટેટસ)

કયા યુઝરે કઈ તારીખે કયો ટાસ્ક પૂરો કર્યો તેનો તારીખવાર રેકોર્ડ.

ફીલ્ડ (Column)ડેટા ટાઇપવિગત અને ઉપયોગ
idINT AUTO_INCREMENT PRIMARY KEYરેકોર્ડ આઈડી.
task_idVARCHAR(64) NOT NULLજે ટાસ્ક પૂરો કર્યો હોય તેનો આઈડી.
categoryVARCHAR(50)કેટેગરી (food, exercise, mental, sleep, habits).
condition_keyVARCHAR(50)કઈ હેલ્થ કન્ડિશન હેઠળ ટાસ્ક પૂરો થયો.
log_dateDATE NOT NULLટાસ્ક પૂરા કર્યાની તારીખ (YYYY-MM-DD).
statusENUM('pending', 'done')સ્થિતિ: 'done' અથવા 'pending'.
user_idINT NOT NULL, FOREIGN KEYજે યુઝરે ટાસ્ક કર્યો હોય તેનો યુઝર આઈડી.

* કમ્પોઝિટ યુનિક કી: (task_id, log_date, condition_key, user_id) જેથી એક જ દિવસમાં એક જ ટાસ્ક બે વાર ડુપ્લિકેટ ન થાય.

૪. user_daily_logs અને user_category_daily_logs ટેબલ્સ

દરેક દિવસના અંતે યુઝરે કુલ કેટલા ટાસ્કમાંથી કેટલા ટાસ્ક પૂરા કર્યા અને તેનો સ્કોર કેટલો થયો (score_percent) તેની ગણતરી સેવ થાય છે. આ ટેબલ પરથી કેલેન્ડરમાં લીલા, પીળા કે લાલ રંગનો હીટમેપ દેખાય છે અને સ્ટ્રીક (Streak) ગણાય છે.

૫. contact_messages ટેબલ

યુઝર્સ દ્વારા વેબસાઇટ પરથી મોકલાયેલા ફીડબેક, પ્રશ્નો અને મેસેજિસ (નામ, ઇમેઇલ, વિષય, મેસેજ) સાચવે છે.

૬. સિક્યોરિટી અને ફોલબેક મિકેનિઝમ (Security & Robustness)

૬.૧ સિક્યોરિટી ફીચર્સ (Security Implementation):

  • પાસવર્ડ એન્ક્રિપ્શન (bcryptjs): પાસવર્ડ ક્યારેય પ્લેન ટેક્સ્ટમાં સેવ થતો નથી. તેને ૧૦ સોલ્ટ રાઉન્ડ્સ (Salt Rounds) સાથે વન-વે હેશ કરીને ડેટાબેઝમાં સાચવવામાં આવે છે.
  • JWT (JSON Web Tokens): સફળ લોગિન પછી સર્વર સિક્રેટ કી સાથે ૭ દિવસની વેલિડિટી વાળો ટોકન આપે છે. ફ્રન્ટએન્ડ દરેક રિક્વેસ્ટમાં Authorization: Bearer <token> મોકલે છે.
  • Helmet HTTP Headers: ક્રોસ-સાઇટ સ્ક્રિપ્ટીંગ (XSS) અને ક્લિકજેકિંગ સામે રક્ષણ આપવા માટે સુરક્ષિત એચટીટીપી હેડર્સ લાગુ કરેલા છે.
  • Rate Limiting (DDoS & Brute Force Prevention): express-rate-limit દ્વારા લોગિન/સાઇનઅપ પર ૧૫ મિનિટમાં મહત્તમ ૧૦૦ રિક્વેસ્ટની મર્યાદા રાખી છે જેથી કોઈ હેકર વારંવાર ખોટા પાસવર્ડ નાખી ન શકે.
  • SQL Injection Prevention: ડેટાબેઝ ક્વેરીઓમાં વેલ્યુ સીધી જોડવાને બદલે પ્રીપેર્ડ સ્ટેટમેન્ટ્સ (? પ્લેસહોલ્ડર) વાપરેલા છે જેથી SQL ઇન્જેક્શન શક્ય નથી.

૬.૨ ઇન-મેમરી રેઝિલિઅન્ટ ફોલબેક મોડ (The In-Memory Fallback):

આ પ્રોજેક્ટની સૌથી મોટી વિશેષતા એ છે કે સર્વર સ્ટાર્ટ થતી વખતે backend/config/db.js માં રહેલો initDB() ફંક્શન MySQL સાથે કનેક્ટ થવાનો પ્રયાસ કરે છે. જો તમારા પ્રેઝન્ટેશન વાળા લેપટોપમાં MySQL સર્વર બંધ હોય કે પાસવર્ડ ખોટો હોય, તો એપ્લિકેશન એરર આપીને બંધ થતી નથી. તે આપમેળે રેઝિલિઅન્ટ ઇન-મેમરી સ્ટોરમાં સ્વિચ થઈ જાય છે અને બધી જ REST APIs મેમરીમાંથી ચાલે છે!

પરીક્ષક (Ma'am) આમાંથી જ પ્રશ્નો પૂછશે. દરેક સભ્ય આ જવાબો મોઢે કરી લેવા:

પ્રશ્ન ૧: તમારા પ્રોજેક્ટનો મુખ્ય ઉદ્દેશ્ય (Purpose/POV) શું છે? Basic
"મેડમ, અમારા પ્રોજેક્ટનો ઉદ્દેશ્ય UN Sustainable Development Goal 3 (Good Health and Well-Being) હેઠળ લોકોને સ્વસ્થ જીવનશૈલી માટે જાગૃત કરવાનો છે. ટેકનિકલ POV એ છે કે આ એક સંપૂર્ણ ફુલ-સ્ટેક વેબ એપ્લિકેશન છે જેમાં રિસ્પોન્સિવ ફ્રન્ટએન્ડ, નોડ/એક્સપ્રેસ બેકએન્ડ અને માય-એસક્યુએલ ડેટાબેઝ સાથે તમામ CRUD ઓપરેશન્સ યોગ્ય રીતે કામ કરે છે."
પ્રશ્ન ૨: આ પ્રોજેક્ટમાં CRUD કઈ રીતે થાય છે? દરેક ઓપરેશન સમજાવો. Core Concept
"મેડમ, પ્રોજેક્ટમાં ચારેય ઓપરેશન્સ આ પ્રમાણે થાય છે:
• Create: યુઝર '+ Add Task' બટનથી નવો ટાસ્ક ઉમેરે છે (POST /api/tasks) અને સાઇન-અપ કરે છે (POST /api/auth/register).
• Read: હોમ પેજ અને કેલેન્ડર પર ડેટાબેઝમાંથી બધા ટાસ્ક અને દૈનિક સ્કોર ફેચ થાય છે (GET /api/tasks).
• Update: ટાસ્કનું નામ કે વિગત એડિટ થાય છે (PUT /api/tasks/:id) અને ચેકબોક્સ ટીક કરવાથી સ્ટેટસ 'done' થાય છે (POST /api/tasks/toggle-completion).
• Delete: ટાસ્કને ડિલીટ કરી શકાય છે (DELETE /api/tasks/:id - Soft Delete)."
પ્રશ્ન ૩: તમે ડેટાબેઝમાં કયા ટેબલ્સ બનાવ્યા છે અને તેમની રિલેશનશિપ શું છે? Database
"અમારા ડેટાબેઝ good_health_db માં મુખ્ય ૮ ટેબલ્સ છે: users (યુઝર લોગિન), પાંચ કેટેગરી ટાસ્ક ટેબલ્સ (tasks_food, tasks_exercise, tasks_mental, tasks_sleep, tasks_habits), task_completions (રોજના પૂરા થયેલા ટાસ્ક) અને user_daily_logs (રોજનો સ્કોર). કેટેગરી ટાસ્ક્સ અને કોમ્પ્લીશન્સમાં user_id એ users(id) સાથે Foreign Key થી જોડાયેલું છે."
પ્રશ્ન ૪: સોફ્ટ ડિલીટ (Soft Delete) એટલે શું અને તમે તે કેમ વાપર્યું? Architecture
"સોફ્ટ ડિલીટમાં ડેટાબેઝમાંથી રેકોર્ડ કાયમ માટે કાઢી નાખવાને બદલે is_active = 0 ફ્લેગ સેટ કરવામાં આવે છે. જો આપણે હાર્ડ ડિલીટ કરીએ, તો તે ટાસ્ક સાથે જોડાયેલો જૂનો કેલેન્ડર હિસ્ટ્રી અને ડેઇલી સ્કોર ખોટો થઈ જાય. ડેટાની ઐતિહાસિક અખંડિતતા (Data Integrity) જાળવવા સોફ્ટ ડિલીટ વાપરવામાં આવ્યું છે."
પ્રશ્ન ૫: Authentication અને Security માટે તમે શું ટેકનિક વાપરી છે? Security
"અમે પાસવર્ડને ક્યારેય પ્લેન ટેક્સ્ટમાં રાખતા નથી. પાસવર્ડ સિક્યોરિટી માટે bcryptjs દ્વારા ૧૦ રાઉન્ડ્સનું હેશિંગ થાય છે. લોગિન થયેલા યુઝરને ઓળખવા માટે JWT (JSON Web Token) વપરાય છે. આ ઉપરાંત હેકર્સથી બચવા Helmet અને બ્રુટ-ફોર્સ અટકાવવા Rate Limiter મિડલવેર મૂકેલું છે."
પ્રશ્ન ૬: જો પરીક્ષા વખતે MySQL બંધ હોય તો તમારો પ્રોજેક્ટ ચાલશે? Robustness
"હા મેડમ, ૧૦૦% ચાલશે! અમે backend/config/db.js માં Resilient In-Memory Fallback બનાવેલું છે. જો MySQL કનેક્ટ ન થાય તો સર્વર ક્રેશ થવાને બદલે જાતે જ ઇન-મેમરી મોડમાં આવી જાય છે અને તમામ CRUD ઓપરેશન્સ અને APIs કોઈપણ ભૂલ વગર સરળતાથી ચાલતા રહે છે."
પ્રશ્ન ૭: ફ્રન્ટએન્ડ અને બેકએન્ડ વચ્ચે ડેટા કેવી રીતે પાસ થાય છે? Networking
"ફ્રન્ટએન્ડ અને બેકએન્ડ વચ્ચે કમ્યુનિકેશન બ્રાઉઝરની સ્ટાન્ડર્ડ JavaScript Fetch API દ્વારા થાય છે. ફ્રન્ટએન્ડ HTTP Headers માં Content-Type: application/json અને JWT Bearer Token મોકલે છે. એક્સપ્રેસ બેકએન્ડ તેને પ્રોસેસ કરીને JSON ફોર્મેટમાં સ્ટેટસ કોડ (200, 201, 400, 401) સાથે રિસ્પોન્સ આપે છે."
પ્રશ્ન ૮: તમારા પ્રોજેક્ટમાં કયા કયા ઇન્ટરેક્ટિવ કેલ્ક્યુલેટર્સ છે? Features
"અમારા પ્રોજેક્ટમાં ૪ મુખ્ય વૈજ્ઞાનિક કેલ્ક્યુલેટર્સ છે: (૧) Water Calculator: વજન મુજબ પાણીનું પ્રમાણ ગણે છે. (૨) 4-7-8 Breathing Circle: માનસિક શાંતિ માટે ગાઈડેડ લાઈવ એનિમેશન. (૩) 90-Min Sleep Calculator: ઊંઘના સાયકલ મુજબ સુવાનો યોગ્ય સમય જણાવે છે. (૪) 5-Minute Stretch Timer: ડેસ્ક જોબ વાળા માટે સ્ટ્રેચિંગ ટાઈમર."

૯. લાઈવ પ્રેઝન્ટેશન આપતી વખતે ડેમો આપવાની સ્ટેપ-બાય-સ્ટેપ રીત

🗣️ સ્ટેપ ૧: ઓપનિંગ સ્પીચ (૩૦ સેકન્ડ્સ)
"ગુડ મોર્નિંગ / આફ્ટરનૂન મેડમ. આજે અમે અમારો પ્રોજેક્ટ 'Good Health and Well-Being' રજૂ કરીએ છીએ, જે સંયુક્ત રાષ્ટ્રના SDG Goal 3 પર આધારિત છે. અમારો મુખ્ય ઉદ્દેશ્ય પ્રોપર વર્કિંગ ફ્રન્ટએન્ડ, બેકએન્ડ અને ડેટાબેઝ સાથે સંપૂર્ણ CRUD ઓપરેશન્સ ધરાવતી ફુલ-સ્ટેક હેલ્થ એપ્લિકેશન બનાવવાનો છે."
💻 સ્ટેપ ૨: સ્ક્રીન પર લાઈવ ડેમો બતાવવાનો ફ્લો
  1. Login Portal: login.html પર જઈને '1-Click Demo Login' બટન દબાવો જેથી પાસવર્ડ ટાઈપ કર્યા વગર તરત લોગિન થઈ જવાય અને નેવબારમાં યુઝરનું નામ દેખાય.
  2. Create Task: હોમ પેજ પર જઈને '+ Add Task' બટન દબાવો. ટાસ્કનું નામ (જેમ કે "Morning 20m Yoga"), ટિપ લખો, આઈકોન પસંદ કરો અને Save કરો. ટાસ્ક તરત લિસ્ટમાં ઉમેરાઈ જશે. (આ Create ઓપરેશન સાબિત કરે છે).
  3. Read Task: પેજ રિફ્રેશ કરો તો પણ ટાસ્ક ડેટાબેઝમાંથી ફેચ થઈને લિસ્ટમાં જળવાઈ રહે છે. (આ Read ઓપરેશન સાબિત કરે છે).
  4. Update & Complete: ટાસ્ક પર એડિટ બટન (✏️) દબાવીને નામ સુધારીને બતાવો. પછી ચેકબોક્સ પર ટીક કરો - ઉપરનો સ્કોર ૦% માંથી વધીને ટકાવારી બતાવશે. (આ Update ઓપરેશન સાબિત કરે છે).
  5. Delete Task: ટાસ્ક પાસે રહેલું ડિલીટ (🗑️) બટન દબાવો અને કન્ફર્મ કરો. ટાસ્ક લિસ્ટમાંથી હટી જશે. (આ Delete ઓપરેશન સાબિત કરે છે).
  6. Interactive Tools: સમય હોય તો food.html પર જઈને Water Calculator માં વજન નાખીને ગણતરી બતાવો અથવા mental-health.html પર 4-7-8 Breathing Circle શરૂ કરીને બતાવો.
